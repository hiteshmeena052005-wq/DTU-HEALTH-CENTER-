🎓 Academic Viva Q&A Guide (Database Architecture)

Q1: How is data stored and handled in this project?

We use a Relational SQLite 3 Database Engine (backed by data/dtu_health.db) with atomic transactions, alongside a synchronized JSON document store (data/database.json). All schema tables (students, doctors, appointments, slots, prescriptions) are structured with primary keys and relational integrity.

Q2: How do real-time updates happen when a student books or cancels?

We implement a Server-Sent Events (SSE) Bus over HTTP (/api/events) combined with the HTML5 BroadcastChannel bus. When a booking or cancellation occurs, the server performs the SQL update and immediately broadcasts the event to all connected doctor and student clients in under 10ms with zero polling lag.

Q3: How is slot capacity overflow prevented?

Slot capacity is gated at 3 levels: (1) Frontend pre-validation blocks submission if booked_count >= max_limit; (2) Server SQL updates clamp count via MIN(max_limit, booked_count + 1); and (3) Auto-reconciliation continuously matches slot count to exact non-cancelled appointments.
